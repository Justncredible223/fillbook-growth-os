# Android Release Signing — Owner Setup

This is a one-time, owner-controlled setup. The signing keystore and its
passwords are the app's permanent identity — they are never generated by an
automated session and never committed to this repo. `android/app/build.gradle.kts`
is already wired to consume them once you provide them; this doc is the exact
sequence to do that.

## Why this matters

Once an app is signed and (eventually) installed/distributed under a given
key, every future update must be signed with **the same key** to be accepted
as an update rather than a conflicting new app. Losing the keystore, or its
passwords, can permanently block shipping compatible updates depending on
where/how the app ends up distributed. Treat it like a permanent credential,
not a build artifact.

**Never put the keystore or its passwords in Git, Slack, email, or any other
place this repo's history or a chat log could retain them.**

---

## STEP 1 — Generate the keystore

Run this yourself, in a terminal, outside of any automated session:

```bash
keytool -genkeypair -v \
  -keystore fillbook-growth-os-release.jks \
  -alias growthos-release \
  -keyalg RSA \
  -keysize 4096 \
  -validity 10000 \
  -storetype PKCS12
```

- `-keyalg RSA -keysize 4096`: a modern, strong key size well above Android's
  minimum (2048) — comfortably good for the life of the app.
- `-validity 10000`: ~27 years. A signing key needs to outlive the app, not
  just the next release.
- No `-storepass`/`-keypass` flags: **on purpose**. Omitting them makes
  `keytool` prompt you interactively (input hidden as you type) instead of
  the password ever appearing in your shell history or a process list. When
  it asks for the key password, you can press Enter to reuse the keystore
  password, or set a separate one.
- It will also prompt for name/org/locale fields (your identity info baked
  into the certificate) — answer those however you'd like; they don't affect
  signing security.

## STEP 2 — Store it outside the repo

Move `fillbook-growth-os-release.jks` to an owner-controlled location that is
**not** inside `C:\Users\justw\fillbook-growth-os` (or any other git working
tree). Recommended:

- **Primary:** a local, non-repo folder you control (e.g. a password
  manager's secure file storage, or an encrypted local folder).
- **Encrypted backup:** a second copy in an encrypted archive (e.g. a
  password-protected 7z/zip, or your OS's encrypted disk image feature)
  stored somewhere durable — not just the same machine as the primary copy.
- **Second secure backup:** a third copy in a different location again (a
  different cloud provider, a physical encrypted drive, etc.) — the goal is
  "no single point of failure can lose this," not redundancy for its own
  sake.

Record the keystore password and key password in a password manager, not a
plain text file next to the keystore.

## STEP 3 — Configure the four required values

`android/app/build.gradle.kts` reads these from either of two sources (either
is fine — pick whichever fits how you work):

**Option A — local properties file** (simplest for building by hand):

Create `android/keystore.properties` (already gitignored — verified, see
below) with:

```properties
storeFile=<absolute path to fillbook-growth-os-release.jks>
storePassword=<your keystore password>
keyAlias=growthos-release
keyPassword=<your key password>
```

**Option B — environment variables** (useful for CI or if you'd rather not
have a properties file on disk at all):

```
GROWTH_OS_KEYSTORE_PATH=<absolute path to fillbook-growth-os-release.jks>
GROWTH_OS_KEYSTORE_PASSWORD=<your keystore password>
GROWTH_OS_KEY_ALIAS=growthos-release
GROWTH_OS_KEY_PASSWORD=<your key password>
```

`keystore.properties` is checked first; environment variables are the
fallback. You only need one of the two.

## STEP 4 — Run the signed release build

From `android/`:

```bash
./gradlew :app:assembleRelease
```

for a signed APK, or:

```bash
./gradlew :app:bundleRelease
```

for a signed AAB (Play Store format). Both read the same signing config —
nothing extra to set up for the AAB path.

If any of the four values above is missing, both tasks refuse to produce
output rather than silently falling back to unsigned/mis-signed — verified
directly against this AGP version:

- `assembleRelease` fails with a clear, named error:
  `SigningConfig "release" is missing required property "storeFile".`
- `bundleRelease` also fails (confirmed -- it does not produce an AAB), but
  with a less friendly `NullPointerException` from bundletool's internals
  rather than a named-property message. This is a known AGP rough edge in
  the bundle-signing path, not a gap in this project's config -- the safety
  property that matters (no unsigned/mis-signed artifact can slip out) holds
  for both. If the raw NPE is ever confusing to debug, `assembleRelease`'s
  cleaner error message will name the exact missing field.

Either way, there is no fallback that lets an unsigned or wrongly-signed
build pass as a release artifact.

## STEP 5 — Locate the output

- Signed APK: `android/app/build/outputs/apk/release/app-release.apk`
- Signed AAB: `android/app/build/outputs/bundle/release/app-release.aab`

(Note the filename changes from `app-release-unsigned.apk` to
`app-release.apk` once real signing is applied — AGP's own naming
convention, not something to configure.)

## STEP 6 — Install it for verification

```bash
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

Launch the app and confirm it behaves like the debug build you've already
verified (same screens, same production backend) — the only difference
should be the signing identity and (if ever enabled later) code shrinking.

## STEP 7 — Verify the certificate fingerprint

```bash
keytool -list -v -keystore fillbook-growth-os-release.jks -alias growthos-release
```

(prompts for the keystore password). Compare the printed SHA-256 fingerprint
against what you expect — useful to confirm you're building with the
keystore you think you are, and this is the exact value some distribution
paths (e.g. Play Console's App Signing) will ask you to register.

---

## Reference: the four config values

| Property (keystore.properties) | Env var (alternative) | Meaning |
|---|---|---|
| `storeFile` | `GROWTH_OS_KEYSTORE_PATH` | Absolute path to the `.jks` file |
| `storePassword` | `GROWTH_OS_KEYSTORE_PASSWORD` | Password protecting the keystore file itself |
| `keyAlias` | `GROWTH_OS_KEY_ALIAS` | The alias you chose in Step 1 (`growthos-release` above) |
| `keyPassword` | `GROWTH_OS_KEY_PASSWORD` | Password protecting that specific key entry |
